# Домашние занятия — ядро платформы

Локальное веб-приложение для онлайн-занятий родителя с ребёнком 3–6 лет.
Ядро = загрузчик модулей + проигрыватель занятий. Модули — только данные
(JSON + ассеты), без произвольного JS. Бэкенд, авторизация и сбор
персональных данных отсутствуют.

## Быстрый старт (одной командой)

```bash
cd app
npm install
npm run dev        # http://localhost:5173
```

Сборка продакшена и предпросмотр (с PWA / Service Worker):

```bash
npm run build
npm run preview    # http://localhost:4173
```

Тесты:

```bash
npm test               # Vitest + React Testing Library (unit/integration)
npx playwright test    # e2e-сценарий занятия (нужен npm run build && npm run preview)
```

## Структура репозитория

```
docs/STAGE1_SPEC.md          — продуктовая спецификация и архитектура (Этап 1)
app/                         — приложение (React + TypeScript + Vite + Tailwind)
  src/core/                  — ядро: registry/loader/player/storage/tts/schema (Zod)
  src/pages|components|hooks — UI: экраны выбора, предпросмотр, плеер, прогресс, настройки
  public/modules/            — «реестр» модулей (раздаётся статикой, без бэкенда)
    registry.json            — список модулей
    demo-core-check/         — технический demo-модуль-заглушка (2 урока)
    broken-demo/             — заведомо битый модуль (проверка понятной ошибки)
```

## Как добавить новый модуль (без изменения кода ядра)

1. Создайте папку `app/public/modules/<module-id>/` со структурой:

   ```
   <module-id>/
     module.json      — манифест (id, версии, возраст, дисциплина, список уроков)
     lessons/*.json   — уроки (шаги и задания)
     assets/*         — картинки/svg (пути относительные, без .. и http:)
   ```

2. Пример манифеста (`module.json`):

   ```json
   {
     "manifestVersion": 1,
     "apiVersion": 1,
     "minCoreVersion": "0.1.0",
     "id": "my-module",
     "title": "Моя первая методика",
     "shortDescription": "Технический пример для проверки загрузчика.",
     "author": "Author Name",
     "license": "CC-BY-4.0",
     "ageRange": { "from": 3, "to": 6 },
     "discipline": "other",
     "lessons": [
       { "file": "lessons/lesson-1.json", "order": 1 }
     ]
   }
   ```

3. Урок — массив шагов; каждый шаг имеет `id`, `type`, `mode`
   (`parent` | `child`) и `parentScript` (текст, который читает родитель).
   Поддерживаемые типы заданий ядра v1: `instruction`, `picture-choice`,
   `match`, `count`, `feature-choice`, `trace-point`, `offline-task`,
   `reflection` (ровно одна, всегда последняя). Полные JSON-схемы —
   в `docs/STAGE1_SPEC.md` и в коде: `src/core/schema/`.

4. Добавьте строку в `app/public/modules/registry.json`:

   ```json
   { "id": "my-module", "path": "my-module/", "enabled": true }
   ```

5. Обновите страницу. Ядро выполнит: fetch манифеста → Zod-валидация →
   проверка совместимости версий → загрузка уроков. Битый или несовместимый
   модуль покажет понятную ошибку на русском и не сломает остальной список.

## Версионирование API модулей

- Ядро принимает `apiVersion <= CORE_SUPPORTED_API` и `minCoreVersion <= версии ядра`.
- Внутри мажорной версии — только additive-изменения (неизвестные поля игнорируются).
- Неизвестный тип шага → сообщение «Ядро не знает тип …», а не падение.

## Оффлайн (PWA)

После первой загрузки приложение работает без сети: оболочка кешируется,
JSON-модули и ассеты отдаются из cache-first (Workbox, `vite-plugin-pwa`).
Работает после `npm run build && npm run preview`; в dev-режиме SW отключён.

## Прогресс и настройки

Прогресс (какой урок/шаг пройден, время, отметки родителя, заметки рефлексии)
и настройки (звук TTS, размер шрифта, таймер) хранятся локально в
localStorage, ключи `hl.settings.v1` / `hl.progress.v1`. Сброс — в «Настройках».
Никаких оценок: экран прогресса показывает факты и наблюдения.

## Критерии приёмки MVP

1. ✅ Запуск одной командой (`npm install && npm run dev`).
2. ✅ Читает `/modules/registry.json` и показывает список модулей.
3. ✅ Demo-модуль подключается как отдельная папка без правки кода ядра.
4. ✅ Проводит demo-урок по шагам (инструкция родителю → экранное задание →
   офлайн-действие → рефлексия); переходы — стрелками, автопрокрутки нет.
5. ✅ Прогресс сохраняется и восстанавливается после перезагрузки страницы.
6. ✅ Повреждённый/несовместимый модуль даёт понятную ошибку (`broken-demo`).
7. ✅ README (этот файл): как добавить модуль, обновить реестр, запустить тесты.
8. ✅ Окно предпросмотра урока: лента шагов в read-only, без записи прогресса.

## Развёртывание в Open Server Panel (OSP) — v1.0

Приложение — чистая статика (Apache/Nginx, PHP не нужен). `base: './'` в vite.config.ts, поэтому работает и в корне домена, и из подпапки.

1. Соберите: `cd app && npm run build` → готовый сайт в `app/dist/`.
2. Скопируйте **содержимое** `app/dist/` в корень сайта OSP: `domains/<ваш-домен>/public/` (или `local/<папка>/`).
3. Откройте `http://<домен>/` (или `http://localhost/<папка>/`) — приложение загружается.
4. Установка PWA: Chrome → адресная строка → «Установить приложение» (иконки 192/512 в манифесте есть; display: standalone).
   ⚠️ Иконки — технические заглушки (генерация из icon.svg), заменить на дизайнерские в v1.1.
5. Офлайн-проверка: первый визит онлайн → отключить сеть → перезагрузить → главная и загруженные модули работают (precache 28 URL, ~373 KiB, включая 12 SVG-листов и m01-start-3-4.zip). Подтверждено e2e-спеком `offline.spec.ts`.
6. Если раздаёте из подпапки — проверьте DevTools → Application → Service Workers: scope должен быть `/<папка>/`. SW регистрируется автоматически (`registerSW.js`, autoUpdate).

Известные ограничения v1.0: страницы `/dev/*` не входят; lesson-flow UX-фикс выполнен в 5.1; тяжёлая a11y — вне скоупа.
